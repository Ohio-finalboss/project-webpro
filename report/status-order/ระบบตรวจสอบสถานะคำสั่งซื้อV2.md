# ระบบตรวจสอบสถานะคำสั่งซื้อ - Technical & Architecture Report

## 1. ภาพรวมสถาปัตยกรรมและเทคโนโลยีที่ใช้ (Architecture & Tech Stack)

ระบบแบ่งเป็น UI Layer (EJS/CSS/Browser JavaScript), Business Logic Layer (Express routes/helpers), Data Layer (SQLite ผ่าน prepared statements) และ External Services ที่โหลดฟอนต์ Prompt จาก Google Fonts; SSE ใช้อัปเดตหน้าเว็บแบบ one-way โดยไม่ต้อง polling.

- **UI Layer:** EJS สร้าง HTML จากข้อมูลที่ server ส่ง; CSS จัดธีม/การแสดงผล; JavaScript ฝั่ง browser จัดการ event, pagination และ live refresh.
- **Business Logic Layer:** Express routes ตรวจค่าจาก request, ควบคุมสถานะคำสั่งซื้อ/ตะกร้า/การชำระ และเลือก view หรือ response.
- **Data Layer:** SQLite เก็บลูกค้า คำสั่งซื้อ รายการช่อ การชำระ และพนักงาน; ใช้ prepared statements ใน server/routes.
- **Tools:** Node.js รัน server; Express จัด HTTP routes/middleware; EJS เลือกเพราะ server สร้าง HTML พร้อมข้อมูลได้โดยตรง; SQLite เหมาะกับฐานข้อมูลไฟล์ในแอปนี้; express-session เก็บ state ของลูกค้าข้ามหน้า; SSE ส่ง event ทางเดียวให้หน้าที่เปิดอยู่โดยไม่ polling; CSS/vanilla JavaScript จัด UI โดยไม่เพิ่ม client framework.

### ลำดับการทำงานและกฎธุรกิจ



1. ลูกค้าเปิด `/check-order-status` แล้วส่ง `order_id` ผ่าน GET query string
2. route trim ID และจำกัดไม่เกิน 30 ตัวอักษร; ค้น `orders.order_ID` แบบไม่แยกตัวพิมพ์เล็ก/ใหญ่
3. เมื่อพบ order เรียก `statusInfo()` แปลงชื่อสถานะเป็น index/tone/cancelled และส่งข้อมูลพร้อม `STATUS_STEPS`/`formatDate` ให้ EJS
4. `check-order-status.ejs` แสดง error เมื่อไม่พบ หรือแสดง badge, progress steps, ลูกค้า, วันรับสินค้า, รูปแบบรับสินค้าและผู้รับผิดชอบ
5. เมื่อพนักงานเปลี่ยนสถานะ หรือเกิดการชำระ/ยกเลิก ฝั่ง server ส่ง `shop-update`; browser GET URL เดิมและแทน `<main data-live-region="customer-order-status">` โดยไม่ reload ทั้งหน้า

### หน้าที่ของฟังก์ชันและ component

### 1. นิยามลำดับและรูปแบบสถานะใน `server.js`

- `STATUS_STEPS`: ลำดับขั้น `รอจัด`, `กำลังจัดช่อ`, `จัดเสร็จแล้ว`, `เสร็จสิ้น`
- `STATUS_CANCELLED`: ค่าที่ใช้ระบุยกเลิก
- `statusInfo(status)`: หา index ของสถานะใน steps; จัด tone เป็น wait/progress/done/cancel/other; ส่ง flag cancelled ให้ view
- `formatDate(value)`: รับค่าว่างเป็น `-`; parse ค่า SQLite; format วัน/เดือน/ปีแบบไทย และถ้ามีเวลาแสดงชั่วโมง/นาทีพร้อม `น.`

### 2. Route `GET /check-order-status`

1. อ่าน `req.query.order_id`, แปลงเป็น string และ trim
2. เตรียม view model เริ่มต้น `searched:false`, `error:null`, `order:null`, `status:null`, `steps`, `formatDate`
3. เมื่อมี query ให้ตั้ง searched; หากยาวเกิน 30 แจ้ง error
4. ถ้าความยาวถูกต้อง query `SELECT * FROM orders WHERE UPPER(order_ID)=UPPER(?)` ด้วย prepared statement
5. ถ้าพบเรียก `statusInfo(order_status)`; ถ้าไม่พบให้ข้อความ error อ้างอิง ID ที่ค้นหา
6. render `check-order-status.ejs`

การค้นนี้อ่านสถานะจาก `orders`; ค่าสถานะ payment แยกอยู่ที่ `payments` และแสดงเฉพาะใน flow หน้าชำระ/พนักงาน ไม่ถูกนำมาปะปนเป็นสถานะออเดอร์

### 3. `views/check-order-status.ejs`

- Head โหลด Prompt, `/style.css`, `/customer-nav.css` และ `/live-updates.js`
- partial customer nav ถูก include โดยกำหนด active เป็น `status`
- ฟอร์ม GET ใช้ field `order_id`, maxlength 30 และคงค่าค้นหาใน input
- EJS เงื่อนไข `searched/error/order` เลือกแสดงผล error หรือ order
- `status.cancelled` แสดงข้อความยกเลิก; ถ้า `status.index >= 0` วน `steps` สร้างลำดับ completed/current/upcoming
- `<dl class="details">` แสดงวันที่, fulfillment, ชื่อลูกค้า, โทรศัพท์, recipient, address และ emp_ID
- `<main data-live-region="customer-order-status">` เป็นจุดที่ client แทนข้อมูลใหม่จาก server

### 4. CSS ของสถานะและต้นทางการเปลี่ยนสถานะ

`public/style.css` กำหนดสีพื้นครีม สีสถานะ การ์ดค้นหา badge steps และรายละเอียด; สี tone ที่ route ส่งเป็น class ใช้แยกสถานะปกติ/คืบหน้า/สำเร็จ/ยกเลิก

สถานะที่เห็นในหน้านี้ถูกเขียนจาก route ของพนักงานใน `server.js`: florist เปลี่ยนรอจัด → กำลังจัดช่อ → จัดเสร็จแล้ว; counter เปลี่ยนขั้นการส่งมอบตาม pickup/delivery; ลูกค้ายกเลิกผ่าน `/payment/cancel/:id` ใน `routes/order-flow.js`. หลังเปลี่ยนสำเร็จทุก route ส่ง SSE signal ให้หน้านี้ดึงสถานะล่าสุด

## 2. การทำงานส่วน Front-End (Client-Side)

แต่ละ source block ด้านล่างเป็นโค้ดจริงจากไฟล์เดิม ไม่มีภาพแทนโค้ด; คำอธิบาย component ระบุผลที่ผู้ใช้เห็นหรือพฤติกรรมที่เกิดขึ้นเมื่อใช้หน้านั้น.

### Source: `views/check-order-status.ejs`

**Component-by-component explanation:**

- `<head>` — กำหนดชื่อหน้า, meta, ฟอนต์, stylesheet และ script ที่หน้าใช้งาน; ไม่ใช่เนื้อหาหลักที่ผู้ใช้เห็น.
- `<header>`, `<nav>`, `<main>`, `<section>`, `<footer>` (ตามที่มี) — แบ่งหน้าเป็นส่วนหัว/นำทาง/เนื้อหาหลัก/ส่วนย่อย/ท้ายหน้า เพื่อจัด layout และลำดับเนื้อหา.
- `<form action="/check-order-status" method="get" class="search-form">` — เมื่อผู้ใช้ submit browser ส่งค่าช่องกรอกไปยัง action ด้วย method ที่ระบุ.
- `<% if/else %>` เลือกเนื้อหาตามข้อมูลจริง เช่น error, empty state หรือสถานะคำสั่งซื้อ; `<% array.forEach(...) %>` สร้างแถว/รายการซ้ำตามจำนวนข้อมูล; `<%= value %>` แสดงข้อมูลแบบ escape; `<%- include(...) %>` แทรก partial HTML ที่ใช้ร่วมกัน.
- `name="viewport"` — บอก browser ให้ปรับขนาดหน้าให้พอดีกับความกว้างอุปกรณ์ จึงช่วยให้ layout แสดงผลเหมาะกับมือถือ.
- `href="https://fonts.googleapis.com"` — เชื่อมต่อบริการฟอนต์ของ Google เพื่อโหลดแบบอักษรที่หน้าเว็บใช้.
- `href="https://fonts.gstatic.com"` — เตรียมการเชื่อมต่อกับ host ที่ส่งไฟล์ฟอนต์ ช่วยให้ browser โหลดฟอนต์ได้เร็วขึ้น.
- `href="https://fonts.googleapis.com/css2?family=Prompt:wght@300;400;500;600&display=swap"` — ให้ browser โหลดฟอนต์ Prompt ที่ใช้แสดงข้อความบนหน้านี้.
- `href="/style.css"` — ให้ browser โหลด stylesheet ซึ่งกำหนดสีและ layout ของหน้านี้.
- `href="/customer-nav.css"` — ให้ browser โหลด stylesheet ซึ่งกำหนดสีและ layout ของหน้านี้.
- `src="/live-updates.js"` — โหลด JavaScript ไฟล์นี้เพื่อเพิ่มพฤติกรรม interactive/อัปเดตหน้า.
- `data-live-region="customer-order-status"` — เป็น hook ให้ CSS/JavaScript ระบุ element หรือบริเวณที่อัปเดต.
- `name="order_id"` — ระบุชื่อ field ที่ส่งกับฟอร์มหรือข้อมูลที่ JavaScript อ่าน.

### Source: `public/live-updates.js`

**Component-by-component explanation:**

- `refreshRegions()` — ฟังก์ชัน/handler นี้ทำงานเมื่อถูกเรียก; พารามิเตอร์ `` เป็นข้อมูลเข้าและผลลัพธ์ส่งต่อให้ route, หน้าเว็บ หรือ callback.
- SSE/event — ส่งสัญญาณข้อมูลเปลี่ยนไปยังหน้าเว็บที่เปิดอยู่ เพื่อให้โหลดเฉพาะส่วนใหม่โดยไม่ refresh ทั้งหน้า.
- Database calls — ใช้ prepared statement อ่าน/บันทึก/เปลี่ยนข้อมูล; route ตรวจผลการ query ก่อนตอบ browser.
- Error handling — จับข้อผิดพลาดจากฐานข้อมูล/การประมวลผล แล้วส่งต่อหรือแสดง error response แทนการปล่อย request ค้าง.


````javascript
(() => {
  const eventStream = new EventSource('/events');
  let updating = false;
  let updateQueued = false;
  let connectedOnce = false;

  async function refreshRegions() {
    const activeElement = document.activeElement;
    if (
      activeElement &&
      activeElement.closest('[data-live-region]') &&
      ['INPUT', 'SELECT', 'TEXTAREA'].includes(activeElement.tagName)
    ) {
      activeElement.addEventListener('blur', refreshRegions, { once: true });
      return;
    }

    if (updating) {
      updateQueued = true;
      return;
    }

    updating = true;
    try {
      const response = await fetch(window.location.href, {
        cache: 'no-store',
        credentials: 'same-origin',
        headers: { Accept: 'text/html', 'X-Live-Update': '1' },
      });
      if (!response.ok) return;

      const responseUrl = new URL(response.url);
      const currentUrl = new URL(window.location.href);
      if (responseUrl.pathname !== currentUrl.pathname || responseUrl.search !== currentUrl.search) {
        window.location.assign(responseUrl.href);
        return;
      }

      const html = await response.text();
      const nextDocument = new DOMParser().parseFromString(html, 'text/html');
      const currentRegions = document.querySelectorAll('[data-live-region]');
      let changed = false;

      currentRegions.forEach((currentRegion) => {
        const regionName = currentRegion.dataset.liveRegion;
        const nextRegion = Array.from(nextDocument.querySelectorAll('[data-live-region]'))
          .find((region) => region.dataset.liveRegion === regionName);
        if (nextRegion) {
          currentRegion.replaceWith(nextRegion);
          changed = true;
        }
      });

      if (changed) window.dispatchEvent(new CustomEvent('sse:updated'));
    } catch {
      // EventSource reconnects automatically; keep the current page usable if refresh fails.
    } finally {
      updating = false;
      if (updateQueued) {
        updateQueued = false;
        refreshRegions();
      }
    }
  }

  eventStream.addEventListener('open', () => {
    if (connectedOnce) refreshRegions();
    connectedOnce = true;
  });
  eventStream.addEventListener('shop-update', refreshRegions);
})();
````

- `formatDate(value)` แปลงวันเวลาฐานข้อมูลเป็นรูปแบบไทย หรือคืน `-` เมื่อไม่มีค่า.

````javascript
const STATUS_STEPS = ['รอจัด', 'กำลังจัดช่อ', 'จัดเสร็จแล้ว', 'เสร็จสิ้น'];
const STATUS_CANCELLED = 'ยกเลิก';

function statusInfo(status) {
  const index = STATUS_STEPS.indexOf(status);
  let tone = 'other';
  if (status === STATUS_CANCELLED) tone = 'cancel';
  else if (index === 0) tone = 'wait';
  else if (index === STATUS_STEPS.length - 1) tone = 'done';
  else if (index > 0) tone = 'progress';
  return { index, tone, cancelled: status === STATUS_CANCELLED };
}

function formatDate(value) {
  if (!value) return '-';
  const date = new Date(String(value).replace(' ', 'T'));
  if (Number.isNaN(date.getTime())) return value;
  const hasTime = /\d{1,2}:\d{2}/.test(value);
  return date.toLocaleString('th-TH', {
    day: 'numeric', month: 'long', year: 'numeric',
    ...(hasTime ? { hour: '2-digit', minute: '2-digit' } : {}),
  }) + (hasTime ? ' น.' : '');
}
````

รายงานนี้อธิบายเฉพาะการเรียกฐานข้อมูลจาก source application; ไฟล์ฐานข้อมูลและ schema ภายใน `db/` ไม่ได้คัดลอกลงเอกสาร. ตารางที่ถูกอ้างอิงใน SQL ของระบบรวมถึง `orders`, `order_details`, `payments`, `bouquets`, `bouquet_items`, `bouquet_templates`, `template_items`, `cart`, `cart_items`, `employees` และตารางที่เกี่ยวข้องกับข้อมูลลูกค้า/การจัดส่ง.

- `SELECT`/`JOIN` อ่านคำสั่งซื้อ รายการช่อ payment และพนักงานเพื่อประกอบข้อมูลหน้า dashboard, รายละเอียด, สถานะ และใบเสร็จ.
- `INSERT` สร้าง cart/order/order_details/payment และรายการส่วนประกอบตามขั้นตอนที่ลูกค้ายืนยัน.
- `UPDATE` เปลี่ยนจำนวนสินค้า สถานะงาน สถานะชำระเงิน ผู้จัด และข้อมูลใบเสร็จ; transaction ใช้ครอบการเขียนหลายตารางใน flow ที่ต้องสำเร็จพร้อมกัน.
- `DELETE` เอารายการตะกร้าออก; คำสั่งยกเลิกจะเปลี่ยนสถานะโดยเก็บข้อมูลคำสั่งซื้อไว้.
- ค่าจากผู้ใช้ส่งเป็น SQL parameters ผ่าน prepared statements เพื่อแยกข้อมูลออกจากคำสั่ง SQL.

**ขอบเขตเอกสาร:** อ้างอิงโค้ด `.js`, `.ejs`, `.css` เท่านั้น ไม่รวม `db/`, ฐานข้อมูล, `nnode_modules/`, dependency หรือไฟล์สื่อ. แต่ละ source block เป็น text code fence พร้อมภาษาและ component notes ที่อธิบายหน้าที่/ผลลัพธ์ของส่วนประกอบ.
