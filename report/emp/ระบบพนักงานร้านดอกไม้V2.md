# ระบบพนักงานร้านดอกไม้ - Technical & Architecture Report

## 1. ภาพรวมสถาปัตยกรรมและเทคโนโลยีที่ใช้ (Architecture & Tech Stack)

ระบบแบ่งเป็น UI Layer (EJS/CSS/Browser JavaScript), Business Logic Layer (Express routes/helpers), Data Layer (SQLite ผ่าน prepared statements) และ External Services ที่โหลดฟอนต์ Prompt จาก Google Fonts; SSE ใช้อัปเดตหน้าเว็บแบบ one-way โดยไม่ต้อง polling.

- **UI Layer:** EJS สร้าง HTML จากข้อมูลที่ server ส่ง; CSS จัดธีม/การแสดงผล; JavaScript ฝั่ง browser จัดการ event, pagination และ live refresh.
- **Business Logic Layer:** Express routes ตรวจค่าจาก request, ควบคุมสถานะคำสั่งซื้อ/ตะกร้า/การชำระ และเลือก view หรือ response.
- **Data Layer:** SQLite เก็บลูกค้า คำสั่งซื้อ รายการช่อ การชำระ และพนักงาน; ใช้ prepared statements ใน server/routes.
- **Tools:** Node.js รัน server; Express จัด HTTP routes/middleware; EJS เลือกเพราะ server สร้าง HTML พร้อมข้อมูลได้โดยตรง; SQLite เหมาะกับฐานข้อมูลไฟล์ในแอปนี้; express-session เก็บ state ของลูกค้าข้ามหน้า; SSE ส่ง event ทางเดียวให้หน้าที่เปิดอยู่โดยไม่ polling; CSS/vanilla JavaScript จัด UI โดยไม่เพิ่ม client framework.

### ลำดับการทำงานและกฎธุรกิจ



1. `server.js` เปิด Express, ตั้ง EJS, โหลด session และเชื่อมฐานข้อมูล จากนั้นเปิด static assets, SSE และ router ของระบบลูกค้า
2. พนักงานเข้า `/employee/florist` หรือ `/employee/counter`; `dashboard()` อ่านจำนวนออเดอร์ จำนวนที่รอจัด จำนวนแจ้งชำระ รายการล่าสุด และรายการสำเร็จ แล้ว render `home.ejs`
3. พนักงานเปิดรายการทั้งหมดหรือคิวเฉพาะผ่าน routes `/employee/florist/orders`, `/employee/florist/progress`, `/employee/counter/orders`, `/employee/counter/tracking` หรือ `/employee/counter/receipts`
4. คลิกแถวเพื่อเปิด `/employee/:role/orders/:orderId`; server อ่านออเดอร์ ช่อและส่วนประกอบ และรายชื่อพนักงานจัดดอกไม้ แล้ว render `order-detail.ejs`
5. เมื่อเปลี่ยนสถานะ florist routes ตรวจ role, สถานะต้นทาง/ปลายทาง และผู้จัดที่เลือกก่อนเขียน `orders`; counter routes ตรวจเงื่อนไขการยืนยันการชำระและการส่งมอบก่อนเขียน DB
6. เมื่อเขียนสำเร็จ server ส่ง `shop-update` ผ่าน SSE ให้ทุกหน้าที่เปิดค้าง หน้ารับ event จะ GET หน้าเดิมและแทนเฉพาะ `data-live-region`; ตารางจะเริ่ม pagination ใหม่
7. หลังยืนยันชำระเงิน counter เปิดใบเสร็จผ่าน `/employee/counter/receipt/:orderId`; `receipt.ejs` แสดงรายละเอียดและปุ่มพิมพ์

### หน้าที่ของฟังก์ชันและ component

### 1. ตั้งค่าระบบและ helper ใน `server.js`

- `get(sql, params)`, `all(sql, params)`, `run(sql, params)`: แยกการอ่านหนึ่งแถว อ่านหลายแถว และเขียนข้อมูลผ่าน prepared statement
- `latestPaymentJoin()`: สร้าง SQL join เฉพาะรายการ payment ล่าสุดของแต่ละ order เพื่อนำสถานะและข้อมูลใบเสร็จไปแสดง
- `getOrderDetail(orderId)`: อ่านข้อมูล order และ payment ล่าสุด ใช้ร่วมกับหน้ารายละเอียด
- `statusInfo(status)`: แปลงสถานะเป็น index/tone/cancelled สำหรับ UI สถานะ
- `formatDate(value)`: จัดรูปแบบวันเวลาไทยและเติม `น.` เมื่อค่ามีเวลา

โค้ดตั้งต้นส่วนนี้สร้าง `app`, เชื่อม SQLite, เปิด `express-session`, เปิด static directory และกำหนด helper รูปแบบเงินให้ EJS ใช้ได้ โดยไม่ query ฐานข้อมูลจาก template โดยตรง

### 2. `dashboard(req, res, next, role)`

อ่าน `COUNT(*)` ของ orders, จำนวนที่อยู่สถานะรอจัด/กำลังจัดช่อซึ่งชำระแล้ว, จำนวนแจ้งชำระ, รายการล่าสุด และรายการสำเร็จ แล้วส่ง `stats`, `recentOrders`, `completedOrders`, `role` ให้ `views/home.ejs` หาก query ผิดพลาดส่งต่อ error middleware

### 3. Routes รายการพนักงาน

- `/employee/:role`: อนุญาตเฉพาะ `florist` หรือ `counter` แล้วเรียก dashboard
- `/employee/florist/orders`: อ่านออเดอร์ทั้งหมด เรียงสถานะตามลำดับงาน แล้วเรียงเวลาเก่าก่อน
- `/employee/florist/progress`: เลือกเฉพาะ `รอจัด`/`กำลังจัดช่อ` และ `payment_status = ชำระแล้ว` เรียงเก่าก่อน
- `/employee/counter/orders`: แสดงออเดอร์ทั้งหมดเรียงสถานะก่อนเวลา
- `/employee/counter/tracking`: เลือกออเดอร์ที่ยังไม่สำเร็จ/ไม่ยกเลิก
- `/employee/counter/receipts`: เลือก payment ที่ลูกค้าแจ้งชำระแล้วเพื่อรอตรวจ

แต่ละ route render `orders.ejs` หรือ `counter-home.ejs` พร้อมข้อมูลที่ query แล้ว จึงแยกเงื่อนไขธุรกิจไว้ฝั่ง server และใช้ EJS ทำหน้าที่แสดงผล

### 4. เปิดรายละเอียดและทำงานของพนักงาน

`GET /employee/:role/orders/:orderId` ตรวจบทบาทและค้น order ถ้าไม่พบใช้ 
ot-found.ejs`; ถ้าพบ อ่านช่อจาก `order_details`, ข้อมูล `bouquets`/`bouquet_templates`, รวมรายการจาก `bouquet_items` หรือ `template_items` และรายชื่อ `employees` ที่ `emp_role` เป็นพนักงานจัดดอกไม้ แล้ว render `order-detail.ejs`

`POST /employee/florist/orders/:orderId/status`:

1. ตรวจ `role === florist` และอนุญาตเฉพาะสถานะ `กำลังจัดช่อ` กับ `จัดเสร็จแล้ว`
2. ตรวจสถานะเดิมว่าเปลี่ยนต่อได้ตาม state transition
3. เมื่อเริ่มจัด ตรวจว่ามี `emp_ID` และ ID นั้นเป็นพนักงานจัดดอกไม้ จากนั้นเขียน `order_status` และ `emp_ID` พร้อมกัน
4. เมื่อจัดเสร็จ เปลี่ยนเฉพาะ `order_status`
5. ตรวจ `changes`; ถ้าไม่มีแถวเปลี่ยนตอบ conflict; ถ้าสำเร็จ publish SSE แล้ว redirect กลับรายละเอียด

`POST /employee/counter/orders/:orderId/payment` อนุญาตเมื่อ payment เป็น `แจ้งชำระเงินแล้ว`; เปลี่ยนเป็น `ชำระแล้ว`, บันทึก `payment_date`, เตรียม `receipt_number`, publish SSE และ redirect ไปใบเสร็จ

`POST /employee/counter/orders/:orderId/status` จำกัดค่าปลายทางเป็น `กำลังจัดส่ง`/`เสร็จสิ้น` และตรวจความสัมพันธ์กับ `fulfillment_type` และสถานะเดิมก่อน update

`GET /employee/counter/receipt/:orderId` อ่าน order กับ payment ล่าสุด ตรวจว่าชำระแล้ว หากไม่มีเลขใบเสร็จสร้างเลขสำรอง แล้วอ่าน bouquet details เพื่อ render ใบเสร็จ

### 6. SSE และการอัปเดตโดยไม่ reload ทั้งหน้า

- `lib/sse.js:createSseHub()` เก็บ response ของ client ใน `Set`; `subscribe()` ส่ง headers `text/event-stream`, `retry: 5000`, heartbeat ทุก 25 วินาที และลบ client เมื่อ response ปิด
- `publishUpdate()` กระจาย event `shop-update` พร้อม payload ว่าง ไม่มีข้อมูลลูกค้าหรือข้อมูล order ใน message
- `public/live-updates.js` เปิด `EventSource('/events')`; เมื่อ event มาถึงใช้ `fetch` กับ URL ปัจจุบัน, parse HTML ด้วย `DOMParser`, หา region ชื่อเดียวกันและ `replaceWith()`; หาก server redirect ไปคนละ route ให้ browser ไปยัง URL ใหม่
- ก่อนแทนบริเวณ หน้าเว็บเลื่อนการ refresh เมื่อผู้ใช้กำลังพิมพ์หรือเลือก `INPUT/SELECT/TEXTAREA`; เมื่อ SSE reconnect จะ fetch ข้อมูลปัจจุบันเพื่อชดเชย event ที่พลาด
- `server.js` เรียก publish หลัง update ของ florist/counter สำเร็จ; `order-flow.js` เรียก publish หลังสร้าง order แจ้งชำระ หรือยกเลิกสำเร็จ

## 2. การทำงานส่วน Front-End (Client-Side)

แต่ละ source block ด้านล่างเป็นโค้ดจริงจากไฟล์เดิม ไม่มีภาพแทนโค้ด; คำอธิบาย component ระบุผลที่ผู้ใช้เห็นหรือพฤติกรรมที่เกิดขึ้นเมื่อใช้หน้านั้น.

### Source: `public/live-updates.js`

**Component-by-component explanation:**

- `refreshRegions()` — ฟังก์ชัน/handler นี้ทำงานเมื่อถูกเรียก; พารามิเตอร์ `` เป็นข้อมูลเข้าและผลลัพธ์ส่งต่อให้ route, หน้าเว็บ หรือ callback.
- SSE/event — ส่งสัญญาณข้อมูลเปลี่ยนไปยังหน้าเว็บที่เปิดอยู่ เพื่อให้โหลดเฉพาะส่วนใหม่โดยไม่ refresh ทั้งหน้า.
- Database calls — ใช้ prepared statement อ่าน/บันทึก/เปลี่ยนข้อมูล; route ตรวจผลการ query ก่อนตอบ browser.
- Error handling — จับข้อผิดพลาดจากฐานข้อมูล/การประมวลผล แล้วส่งต่อหรือแสดง error response แทนการปล่อย request ค้าง.


````javascript
(() => {
  const eventStream = new EventSource('/events');
  let updating = false;
  let updateQueued = false;
  let connectedOnce = false;

  async function refreshRegions() {
    const activeElement = document.activeElement;
    if (
      activeElement &&
      activeElement.closest('[data-live-region]') &&
      ['INPUT', 'SELECT', 'TEXTAREA'].includes(activeElement.tagName)
    ) {
      activeElement.addEventListener('blur', refreshRegions, { once: true });
      return;
    }

    if (updating) {
      updateQueued = true;
      return;
    }

    updating = true;
    try {
      const response = await fetch(window.location.href, {
        cache: 'no-store',
        credentials: 'same-origin',
        headers: { Accept: 'text/html', 'X-Live-Update': '1' },
      });
      if (!response.ok) return;

      const responseUrl = new URL(response.url);
      const currentUrl = new URL(window.location.href);
      if (responseUrl.pathname !== currentUrl.pathname || responseUrl.search !== currentUrl.search) {
        window.location.assign(responseUrl.href);
        return;
      }

      const html = await response.text();
      const nextDocument = new DOMParser().parseFromString(html, 'text/html');
      const currentRegions = document.querySelectorAll('[data-live-region]');
      let changed = false;

      currentRegions.forEach((currentRegion) => {
        const regionName = currentRegion.dataset.liveRegion;
        const nextRegion = Array.from(nextDocument.querySelectorAll('[data-live-region]'))
          .find((region) => region.dataset.liveRegion === regionName);
        if (nextRegion) {
          currentRegion.replaceWith(nextRegion);
          changed = true;
        }
      });

      if (changed) window.dispatchEvent(new CustomEvent('sse:updated'));
    } catch {
      // EventSource reconnects automatically; keep the current page usable if refresh fails.
    } finally {
      updating = false;
      if (updateQueued) {
        updateQueued = false;
        refreshRegions();
      }
    }
  }

  eventStream.addEventListener('open', () => {
    if (connectedOnce) refreshRegions();
    connectedOnce = true;
  });
  eventStream.addEventListener('shop-update', refreshRegions);
})();
````

### Source: `public/table-pagination.js`

**Component-by-component explanation:**

- `initializeTablePagination()` — ฟังก์ชัน/handler นี้ทำงานเมื่อถูกเรียก; พารามิเตอร์ `` เป็นข้อมูลเข้าและผลลัพธ์ส่งต่อให้ route, หน้าเว็บ หรือ callback.
- `updatePage()` — ฟังก์ชัน/handler นี้ทำงานเมื่อถูกเรียก; พารามิเตอร์ `` เป็นข้อมูลเข้าและผลลัพธ์ส่งต่อให้ route, หน้าเว็บ หรือ callback.
- SSE/event — ส่งสัญญาณข้อมูลเปลี่ยนไปยังหน้าเว็บที่เปิดอยู่ เพื่อให้โหลดเฉพาะส่วนใหม่โดยไม่ refresh ทั้งหน้า.
- Database calls — ใช้ prepared statement อ่าน/บันทึก/เปลี่ยนข้อมูล; route ตรวจผลการ query ก่อนตอบ browser.


````javascript
(() => {
  const pageSize = 10;

  function initializeTablePagination() {
    document.querySelectorAll('table').forEach((table) => {
      if (table.dataset.paginationReady) return;
      table.dataset.paginationReady = 'true';

      const rows = Array.from(table.tBodies).flatMap((tbody) => Array.from(tbody.rows));
      if (rows.length <= pageSize) return;

      const controls = document.createElement('nav');
      controls.className = 'table-pagination';
      controls.setAttribute('aria-label', 'เปลี่ยนหน้าตาราง');

      const summary = document.createElement('span');
      summary.className = 'table-pagination-summary';
      const pageLabel = document.createElement('span');
      pageLabel.className = 'table-pagination-page';

      const previous = document.createElement('button');
      previous.type = 'button';
      previous.textContent = 'ก่อนหน้า';
      previous.setAttribute('aria-label', 'หน้าก่อนหน้า');
      const next = document.createElement('button');
      next.type = 'button';
      next.textContent = 'ถัดไป';
      next.setAttribute('aria-label', 'หน้าถัดไป');

      const pageCount = Math.ceil(rows.length / pageSize);
      let page = 1;
      const updatePage = () => {
        const start = (page - 1) * pageSize;
        const end = Math.min(start + pageSize, rows.length);
        rows.forEach((row, index) => {
          row.hidden = index < start || index >= end;
        });
        summary.textContent = `แสดง ${start + 1}–${end} จาก ${rows.length} รายการ`;
        pageLabel.textContent = `หน้า ${page} จาก ${pageCount}`;
        previous.disabled = page === 1;
        next.disabled = page === pageCount;
      };

      previous.addEventListener('click', () => {
        if (page > 1) { page -= 1; updatePage(); }
      });
      next.addEventListener('click', () => {
        if (page < pageCount) { page += 1; updatePage(); }
      });

      controls.append(previous, summary, pageLabel, next);
      const container = table.closest('.table-scroll, .table-wrap') || table;
      container.insertAdjacentElement('afterend', controls);
      updatePage();
    });
  }

  document.addEventListener('DOMContentLoaded', initializeTablePagination);
  window.addEventListener('sse:updated', initializeTablePagination);
})();
````

````javascript
const STATUS_CANCELLED = 'ยกเลิก';

function statusInfo(status) {
  const index = STATUS_STEPS.indexOf(status);
  let tone = 'other';
  if (status === STATUS_CANCELLED) tone = 'cancel';
  else if (index === 0) tone = 'wait';
  else if (index === STATUS_STEPS.length - 1) tone = 'done';
  else if (index > 0) tone = 'progress';
  return { index, tone, cancelled: status === STATUS_CANCELLED };
}

function formatDate(value) {
  if (!value) return '-';
  const date = new Date(String(value).replace(' ', 'T'));
  if (Number.isNaN(date.getTime())) return value;
  const hasTime = /\d{1,2}:\d{2}/.test(value);
  return date.toLocaleString('th-TH', {
    day: 'numeric', month: 'long', year: 'numeric',
    ...(hasTime ? { hour: '2-digit', minute: '2-digit' } : {}),
  }) + (hasTime ? ' น.' : '');
}

app.post('/employee/florist/orders/:orderId/status', (req, res, next) => {
  const role = 'florist';
  const allowedStatuses = ['กำลังจัดช่อ', 'จัดเสร็จแล้ว'];
  if (req.body.role !== 'florist') return res.sendStatus(403);
  if (!allowedStatuses.includes(req.body.status)) return res.status(400).send('สถานะคำสั่งซื้อไม่ถูกต้อง');

  try {
    const order = get('SELECT order_status, emp_ID FROM orders WHERE order_ID = ?', [req.params.orderId]);
    if (!order) return res.status(404).render('not-found', { role });
    const nextStatuses = {
      รอจัด: ['กำลังจัดช่อ'],
      กำลังจัดช่อ: ['จัดเสร็จแล้ว'],
    };
    if (!(nextStatuses[order.order_status] || []).includes(req.body.status)) {
      return res.status(409).send('สถานะออเดอร์เปลี่ยนไปแล้ว กรุณาโหลดหน้าอีกครั้ง');
    }
    if (req.body.status === 'กำลังจัดช่อ') {
      const employeeId = String(req.body.emp_ID || '').trim();
      if (!employeeId) return res.status(400).send('กรุณาเลือกพนักงานจัดดอกไม้');
      const employee = get(
        "SELECT emp_ID FROM employees WHERE emp_ID = ? AND emp_role = 'พนักงานจัดดอกไม้'",
        [employeeId],
      );
      if (!employee) return res.status(400).send('เลือกได้เฉพาะพนักงานจัดดอกไม้');
      const result = run(
        'UPDATE orders SET order_status = ?, emp_ID = ? WHERE order_ID = ? AND order_status = ?',
        [req.body.status, employee.emp_ID, req.params.orderId, order.order_status],
      );
      if (!result.changes) return res.status(409).send('สถานะออเดอร์เปลี่ยนไปแล้ว กรุณาโหลดหน้าอีกครั้ง');
      sseHub.publishUpdate();
      return res.redirect(`/employee/florist/orders/${encodeURIComponent(req.params.orderId)}`);
    }

    const result = run(
      'UPDATE orders SET order_status = ? WHERE order_ID = ? AND order_status = ?',
      [req.body.status, req.params.orderId, order.order_status],
    );
    if (!result.changes) return res.status(404).render('not-found', { role });
    sseHub.publishUpdate();
    return res.redirect(`/employee/florist/orders/${encodeURIComponent(req.params.orderId)}`);
  } catch (error) {
    return next(error);
  }
});

      ? (order.order_status === 'จัดเสร็จแล้ว' ? 'กำลังจัดส่ง' : order.order_status === 'กำลังจัดส่ง' ? 'เสร็จสิ้น' : null)
      : (order.order_status === 'จัดเสร็จแล้ว' ? 'เสร็จสิ้น' : null);
    if (req.body.status !== allowedNextStatus) {
      return res.status(409).send('อัปเดตการส่งมอบได้หลังจัดช่อเสร็จแล้ว');
    }
    const result = run('UPDATE orders SET order_status = ? WHERE order_ID = ?', [req.body.status, req.params.orderId]);
    if (!result.changes) return res.status(404).render('not-found', { role: 'counter' });
    sseHub.publishUpdate();
    return res.redirect(`/employee/counter/orders/${encodeURIComponent(req.params.orderId)}`);
  } catch (error) {
    return next(error);
  }
});
````

````javascript
function createSseHub() {
  const clients = new Set();

  function publishUpdate() {
    const message = 'event: shop-update\ndata: {}\n\n';

    for (const response of clients) {
      try {
        response.write(message);
      } catch {
        clients.delete(response);
      }
    }
  }

  function subscribe(req, res) {
    res.set({
      'Content-Type': 'text/event-stream; charset=utf-8',
      'Cache-Control': 'no-cache, no-transform',
      Connection: 'keep-alive',
      'X-Accel-Buffering': 'no',
    });
    res.flushHeaders();
    res.write('retry: 5000\n\n');

    clients.add(res);
    const heartbeat = setInterval(() => {
      if (!res.writableEnded) res.write(': keep-alive\n\n');
    }, 25000);

    res.on('close', () => {
      clearInterval(heartbeat);
      clients.delete(res);
    });
  }

  return { publishUpdate, subscribe };
}

module.exports = createSseHub;
````

**ผลของคำสั่ง:** SELECT จำกัดผู้ที่ assign ได้เฉพาะ role พนักงานจัดดอกไม้; UPDATE บันทึกสถานะและผู้จัดพร้อมกัน และเช็คสถานะเดิมเพื่อป้องกันการเขียนทับข้อมูลที่เปลี่ยนไปแล้ว.


รายงานนี้อธิบายเฉพาะการเรียกฐานข้อมูลจาก source application; ไฟล์ฐานข้อมูลและ schema ภายใน `db/` ไม่ได้คัดลอกลงเอกสาร. ตารางที่ถูกอ้างอิงใน SQL ของระบบรวมถึง `orders`, `order_details`, `payments`, `bouquets`, `bouquet_items`, `bouquet_templates`, `template_items`, `cart`, `cart_items`, `employees` และตารางที่เกี่ยวข้องกับข้อมูลลูกค้า/การจัดส่ง.

- `UPDATE` เปลี่ยนจำนวนสินค้า สถานะงาน สถานะชำระเงิน ผู้จัด และข้อมูลใบเสร็จ; transaction ใช้ครอบการเขียนหลายตารางใน flow ที่ต้องสำเร็จพร้อมกัน.
